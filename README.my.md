# ကုတ်ပြန်လည်သုံးသပ်ခြင်း ပလပ်အင်

ယုံကြည်မှုအခြေခံ အမှတ်ပေးစနစ်ဖြင့် မှားယွင်းသော အပေါင်းလက္ခဏာများကို စစ်ထုတ်ရန်အတွက် အထူးပြုကိုယ်စားလှယ်များစွာကို အသုံးပြု၍ pull request များအတွက် အလိုအလျောက်ကုတ်ပြန်လည်သုံးသပ်ခြင်း။

## ခြုံငုံသုံးသပ်ချက်

ကုတ်ပြန်လည်သုံးသပ်ခြင်း ပလပ်အင်သည် pull request ပြန်လည်သုံးသပ်ခြင်းကို အလိုအလျောက်လုပ်ဆောင်သည်။ ၎င်းသည် ပြောင်းလဲမှုများကို မတူညီသော ရှုထောင့်များမှ လွတ်လပ်စွာ စစ်ဆေးရန်အတွက် ကိုယ်စားလှယ်များစွာကို ပြိုင်တူ စတင်အသုံးပြုသည်။ ၎င်းသည် မှားယွင်းသော အပေါင်းလက္ခဏာများကို စစ်ထုတ်ရန်အတွက် ယုံကြည်မှု အမှတ်ပေးစနစ်ကို အသုံးပြုပြီး အရည်အသွေးမြင့်မားသော၊ လုပ်ဆောင်နိုင်သော တုံ့ပြန်ချက်များကိုသာ တင်ပြကြောင်း သေချာစေသည်။

## အမိန့်များ

### '/code-review'

အထူးပြုကိုယ်စားလှယ်များစွာကို အသုံးပြု၍ pull request ပေါ်တွင် အလိုအလျောက်ကုတ်ပြန်လည်သုံးသပ်ခြင်းကို လုပ်ဆောင်သည်။

**၎င်းလုပ်ဆောင်သည်များ:**
1. ပြန်လည်သုံးသပ်ရန် လိုအပ်သည်ရှိမရှိ စစ်ဆေးသည် (ပိတ်ထားသော၊ မူကြမ်း၊ သာမန် သို့မဟုတ် ပြန်လည်သုံးသပ်ပြီးသော PR များကို ကျော်သွားသည်)
2. repository မှ သက်ဆိုင်ရာ CLAUDE.md လမ်းညွှန်ဖိုင်များကို စုဆောင်းသည်
3. pull request ပြောင်းလဲမှုများကို အကျဉ်းချုပ်ဖော်ပြသည်
4. လွတ်လပ်စွာ ပြန်လည်သုံးသပ်ရန် ကိုယ်စားလှယ် ၄ ဦးကို ပြိုင်တူ စတင်အသုံးပြုသည်:
   - **ကိုယ်စားလှယ် #1 & #2**: CLAUDE.md လိုက်နာမှုအတွက် စစ်ဆေးသည်
   - **ကိုယ်စားလှယ် #3**: ပြောင်းလဲမှုများတွင် ထင်ရှားသော bug များကို ရှာဖွေသည်
   - **ကိုယ်စားလှယ် #4**: ဆက်စပ်အခြေအနေအလိုက် ပြဿနာများအတွက် git blame/history ကို ခွဲခြမ်းစိတ်ဖြာသည်
5. ပြဿနာတစ်ခုချင်းစီကို ယုံကြည်မှုအဆင့်အတွက် 0-100 အထိ အမှတ်ပေးသည်
6. 80 ယုံကြည်မှုအမှတ်အောက်ရှိသော ပြဿနာများကို စစ်ထုတ်သည်
7. ပြန်လည်သုံးသပ်ခြင်းကို ထုတ်ပြန်သည် (ပုံမှန်အားဖြင့် terminal သို့၊ သို့မဟုတ် '--comment' flag ဖြင့် PR comment အဖြစ်)

**အသုံးပြုပုံ:**
'''bash
/code-review [--comment]
'''

**ရွေးချယ်စရာများ:**
 - '--comment': ပြန်လည်သုံးသပ်ခြင်းကို pull request ပေါ်တွင် comment အဖြစ်တင်ရန် (ပုံမှန်အားဖြင့် terminal သို့သာ ထုတ်ပြန်သည်)

**ဥပမာ လုပ်ဆောင်မှုစီးဆင်းမှု:**
'''bash
# PR branch ပေါ်တွင်၊ local တွင် run ပါ (terminal သို့ ထုတ်ပြန်သည်):
/code-review

# ပြန်လည်သုံးသပ်ခြင်းကို PR comment အဖြစ်တင်ရန်:
/code-review --comment

# Claude က လုပ်ဆောင်မည်:
# - ပြန်လည်သုံးသပ်ရေး ကိုယ်စားလှယ် ၄ ဦးကို ပြိုင်တူ စတင်အသုံးပြုမည်
# - ပြဿနာတစ်ခုချင်းစီကို ယုံကြည်မှုအတွက် အမှတ်ပေးမည်
# - ≥80 ယုံကြည်မှုရှိသော ပြဿနာများကို ထုတ်ပြန်မည် (flag ပေါ်မူတည်၍ terminal သို့မဟုတ် PR သို့)
# - ယုံကြည်မှုမြင့်မားသော ပြဿနာများ မတွေ့ရှိပါက ကျော်သွားမည်
'''

**အင်္ဂါရပ်များ:**
 - ပြည့်စုံသော ပြန်လည်သုံးသပ်ခြင်းအတွက် လွတ်လပ်သော ကိုယ်စားလှယ်များစွာ
 - ယုံကြည်မှုအခြေခံ အမှတ်ပေးစနစ်သည် မှားယွင်းသော အပေါင်းလက္ခဏာများကို လျှော့ချသည် (အမှတ်: 80)
 - CLAUDE.md လိုက်နာမှုစစ်ဆေးခြင်းကို ရှင်းလင်းသော လမ်းညွှန်ချက်အတည်ပြုချက်ဖြင့် လုပ်ဆောင်သည်
 - ပြောင်းလဲမှုများတွင်သာ အာရုံစိုက်သော bug ရှာဖွေခြင်း (ရှိပြီးသား ပြဿနာများတွင် မဟုတ်)
 - git blame/history မှတစ်ဆင့် သမိုင်းကြောင်းဆိုင်ရာ ဆက်စပ်အခြေအနေကို ခွဲခြမ်းစိတ်ဖြာခြင်း
 - ပိတ်ထားသော၊ မူကြမ်း၊ သို့မဟုတ် ပြန်လည်သုံးသပ်ပြီးသော PR များကို အလိုအလျောက် ကျော်သွားခြင်း
 - ပြည့်စုံသော SHA နှင့် line range ဖြင့် code သို့ တိုက်ရိုက် link ချိတ်ခြင်း

**ပြန်လည်သုံးသပ် comment format:**
'''markdown
## ကုတ်ပြန်လည်သုံးသပ်ခြင်း

ပြဿနာ ၃ ခု တွေ့ရှိ:

1. OAuth callback အတွက် error handling မရှိခြင်း (CLAUDE.md က OAuth error များကို အမြဲကိုင်တွယ်ရန် ပြောသည်)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. Memory leak: OAuth state မရှင်းလင်းရသေးခြင်း (finally block တွင် cleanup မရှိခြင်းကြောင့် bug)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. နာမည်ပေးပုံစံ မကိုက်ညီခြင်း (src/conventions/CLAUDE.md က function များအတွက် camelCase ကိုသုံးရန် ပြောသည်)

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**ယုံကြည်မှုအမှတ်ပေးစနစ်:**
 - **0**: ယုံကြည်မှုမရှိ၊ မှားယွင်းသော အပေါင်းလက္ခဏာ
 - **25**: တစ်စိတ်တစ်ပိုင်းယုံကြည်မှုရှိ၊ ဖြစ်နိုင်သည်
 - **50**: အသင့်အတင့်ယုံကြည်မှုရှိ၊ မှန်သော်လည်း အသေးအမွှယ်
 - **75**: အလွန်ယုံကြည်မှုရှိ၊ မှန်ကန်ပြီး အရေးကြီးသည်
 - **100**: လုံးဝသေချာသည်၊ အမှန်တကယ် မှန်ကန်သည်

**စစ်ထုတ်ပြီးသော မှားယွင်းသော အပေါင်းလက္ခဏာများ:**
 - PR တွင် မိတ်ဆက်မထားသော ရှိပြီးသား ပြဿနာများ
 - bug ကဲ့သို့ ထင်ရသော်လည်း မဟုတ်သော code
 - အသေးအမွှယ် ဝေဖန်မှုများ
 - linters များ ဖမ်းယူမည့် ပြဿနာများ
 - အထွေထွေ အရည်အသွေး ပြဿနာများ (CLAUDE.md တွင် မပါဝင်လျှင်)
 - lint ignore comments ပါရှိသော ပြဿနာများ

## တပ်ဆင်ခြင်း

ဤပလပ်အင်ကို Claude Code repository တွင် ထည့်သွင်းထားသည်။ Claude Code ကို အသုံးပြုသည့်အခါ command သည် အလိုအလျောက် ရရှိနိုင်သည်။

## အကောင်းဆုံး အလေ့အကျင့်များ

### '/code-review' ကို အသုံးပြုခြင်း
 - ပိုမိုကောင်းမွန်သော လိုက်နာမှုစစ်ဆေးခြင်းအတွက် ရှင်းလင်းသော CLAUDE.md ဖိုင်များကို ထိန်းသိမ်းထားပါ
 - 80+ ယုံကြည်မှုအမှတ်အသားကို ယုံကြည်ပါ - မှားယွင်းသော အပေါင်းလက္ခဏာများကို စစ်ထုတ်ပြီးသားဖြစ်သည်
 - သာမန်မဟုတ်သော pull request များအားလုံးတွင် run ပါ
 - လူသားပြန်လည်သုံးသပ်ခြင်းအတွက် ကိုယ်စားလှယ်၏ တွေ့ရှိချက်များကို အစမှတ်အဖြစ် သုံးသပ်ပါ
 - ထပ်ခါတလဲလဲ ပြန်လည်သုံးသပ်မှုပုံစံများအပေါ် အခြေခံ၍ CLAUDE.md ကို အပ်ဒိတ်လုပ်ပါ

### ဘယ်အချိန်မှာ သုံးသင့်လဲ
 - အဓိပ္ပာယ်ရှိသော ပြောင်းလဲမှုများရှိသော pull request များအားလုံး
 - အရေးကြီးသော code path များကို ထိမိသော PR များ
 - ပါဝင်ပတ်သက်သူများစွာမှ PR များ
 - လမ်းညွှန်ချက်လိုက်နာမှု အရေးကြီးသော PR များ

### ဘယ်အချိန်မှာ မသုံးသင့်ဘူးလဲ
 - ပိတ်ထားသော သို့မဟုတ် မူကြမ်း PR များ (အလိုအလျောက် ကျော်သွားပြီးသား)
 - သာမန် အလိုအလျောက် PR များ (အလိုအလျောက် ကျော်သွားပြီးသား)
 - ချက်ချင်းပေါင်းစည်းရန် လိုအပ်သော အရေးပေါ် hotfix များ
 - ပြန်လည်သုံးသပ်ပြီးသော PR များ (အလိုအလျောက် ကျော်သွားပြီးသား)

## လုပ်ဆောင်မှု စီးဆင်းမှု ပေါင်းစည်းခြင်း

### စံ PR ပြန်လည်သုံးသပ်မှု လုပ်ဆောင်မှုစီးဆင်းမှု:
'''bash
# ပြောင်းလဲမှုများဖြင့် PR ကို ဖန်တီးပါ
# local ပြန်လည်သုံးသပ်ခြင်းကို run ပါ (terminal သို့ ထုတ်ပြန်သည်)
/code-review

# အလိုအလျောက် တုံ့ပြန်ချက်ကို ပြန်လည်သုံးသပ်ပါ
# လိုအပ်သော ပြင်ဆင်မှုများ ပြုလုပ်ပါ

# ရွေးချယ်နိုင်သည်မှာ PR comment အဖြစ်တင်ပါ
/code-review --comment

# အဆင်သင့်ဖြစ်သောအခါ ပေါင်းစည်းပါ
'''

### CI/CD ၏ အစိတ်အပိုင်းအဖြစ်:
'''bash
# PR ဖန်တီးခြင်း သို့မဟုတ် အပ်ဒိတ်လုပ်ခြင်းတွင် trigger လုပ်ပါ
# ပြန်လည်သုံးသပ် comment များ တင်ရန် --comment flag ကိုသုံးပါ
/code-review --comment
# ပြန်လည်သုံးသပ်ခြင်း ရှိပြီးသားဖြစ်ပါက ကျော်သွားပါ
'''

## လိုအပ်ချက်များ

 - GitHub ပေါင်းစည်းမှုဖြင့် Git repository
 - GitHub CLI ('gh') ကို ထည့်သွင်းပြီး အတည်ပြုပြီးသားဖြစ်ရမည်
 - CLAUDE.md ဖိုင်များ (ရွေးချယ်နိုင်သည်၊ သို့သော် လမ်းညွှန်ချက်စစ်ဆေးခြင်းအတွက် အကြံပြုသည်)

## ပြဿနာဖြေရှင်းခြင်း

### ပြန်လည်သုံးသပ်ခြင်း အချိန်ကြာမြင့်ခြင်း

**ပြဿနာ**: ကိုယ်စားလှယ်များသည် PR ကြီးများတွင် နှေးကွေးသည်

**ဖြေရှင်းချက်**:
 - ကြီးမားသော ပြောင်းလဲမှုများအတွက် ပုံမှန်ဖြစ်သည် - ကိုယ်စားလှယ်များသည် ပြိုင်တူ လုပ်ဆောင်သည်
 - လွတ်လပ်သော ကိုယ်စားလှယ် ၄ ဦးသည် ပြည့်စုံမှုကို သေချာစေသည်
 - ကြီးမားသော PR များကို သေးငယ်သော PR များအဖြစ် ခွဲရန် စဉ်းစားပါ

### မှားယွင်းသော အပေါင်းလက္ခဏာများ အလွန်များခြင်း

**ပြဿနာ**: ပြန်လည်သုံးသပ်ခြင်းက အမှန်တကယ် မဟုတ်သော ပြဿနာများကို ဖော်ပြသည်

**ဖြေရှင်းချက်**:
 - ပုံမှန်အမှတ် 80 ဖြစ်သည် (မှားယွင်းသော အပေါင်းလက္ခဏာအများစုကို စစ်ထုတ်ပြီးသား)
 - အရေးကြီးသည့်အရာများအကြောင်း CLAUDE.md ကို ပိုမိုတိကျအောင် လုပ်ပါ
 - ဖော်ပြထားသော ပြဿနာသည် အမှန်တကယ် မှန်ကန်သည်ရှိမရှိ စဉ်းစားပါ

### ပြန်လည်သုံးသပ် comment မတင်ခြင်း

**ပြဿနာ**: '/code-review' run ခဲ့သော်လည်း comment မပေါ်ပါ

**ဖြေရှင်းချက်**:
အောက်ပါတို့ကို စစ်ဆေးပါ:
 - PR ကို ပိတ်ထားသည်ရှိမရှိ (ပြန်လည်သုံးသပ်ခြင်းများ ကျော်သွားသည်)
 - PR သည် မူကြမ်းဖြစ်သည်ရှိမရှိ (ပြန်လည်သုံးသပ်ခြင်းများ ကျော်သွားသည်)
 - PR သည် သာမန်/အလိုအလျောက်ဖြစ်သည်ရှိမရှိ (ပြန်လည်သုံးသပ်ခြင်းများ ကျော်သွားသည်)
 - PR တွင် ပြန်လည်သုံးသပ်ခြင်း ရှိပြီးသားဖြစ်သည်ရှိမရှိ (ပြန်လည်သုံးသပ်ခြင်းများ ကျော်သွားသည်)
 - ≥80 အမှတ်ရရှိသော ပြဿနာများ မရှိပါက (comment မလိုအပ်ပါ)

### Link format ပျက်စီးခြင်း

**ပြဿနာ**: GitHub တွင် code link များ မှန်ကန်စွာ မပေါ်ပါ

**ဖြေရှင်းချက်**:
Link များသည် ဤအတိုင်း အတိအကျဖြစ်ရမည်:
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - အပြည့်အစုံ SHA ကိုသုံးရမည် (အတိုကောက် မဟုတ်)
 - '#L' သင်္ကေတကိုသုံးရမည်
 - အနည်းဆုံး 1 line context ပါသော line range ကို ထည့်သွင်းရမည်

### GitHub CLI အလုပ်မလုပ်ခြင်း

**ပြဿနာ**: 'gh' command များ မအောင်မြင်ပါ

**ဖြေရှင်းချက်**:
 - GitHub CLI ကို ထည့်သွင်းပါ: 'brew install gh' (macOS) သို့မဟုတ် [GitHub CLI installation](https://cli.github.com/) ကို ကြည့်ပါ
 - အတည်ပြုပါ: 'gh auth login'
 - repository တွင် GitHub remote ရှိသည်ရှိမရှိ စစ်ဆေးပါ

## အကြံပြုချက်များ

 - **တိကျသော CLAUDE.md ဖိုင်များကို ရေးပါ**: ရှင်းလင်းသော လမ်းညွှန်ချက်များ = ပိုမိုကောင်းမွန်သော ပြန်လည်သုံးသပ်ခြင်းများ
 - **PR များတွင် ဆက်စပ်အခြေအနေကို ထည့်သွင်းပါ**: ကိုယ်စားလှယ်များ ရည်ရွယ်ချက်ကို နားလည်ရန် ကူညီသည်
 - **ယုံကြည်မှုအမှတ်များကို အသုံးပြုပါ**: ≥80 ပြဿနာများသည် များသောအားဖြင့် မှန်ကန်သည်
 - **လမ်းညွှန်ချက်များကို ပြန်လည်လုပ်ဆောင်ပါ**: ပုံစံများအပေါ် အခြေခံ၍ CLAUDE.md ကို အပ်ဒိတ်လုပ်ပါ
 - **အလိုအလျောက် ပြန်လည်သုံးသပ်ပါ**: PR လုပ်ဆောင်မှုစီးဆင်းမှု၏ အစိတ်အပိုင်းအဖြစ် သတ်မှတ်ပါ
 - **စစ်ထုတ်ခြင်းကို ယုံကြည်ပါ**: အမှတ်အသားသည် အပိုဆူညံသံများကို တားဆီးသည်

## စီမံခန့်ခွဲမှု

### ယုံကြည်မှု အမှတ်အသားကို ချိန်ညှိခြင်း

ပုံမှန်အမှတ် 80 ဖြစ်သည်။ ချိန်ညှိရန်အတွက် 'commands/code-review.md' ရှိ command ဖိုင်ကို ပြုပြင်ပါ:
'''markdown
80 အောက် အမှတ်ရရှိသော မည်သည့် ပြဿနာကိုမဆို စစ်ထုတ်ပါ။
'''

'80' ကို သင်နှစ်သက်သော အမှတ်အသား (0-100) သို့ ပြောင်းပါ။

### ပြန်လည်သုံးသပ်မှု အာရုံစိုက်မှုကို စိတ်ကြိုက်ပြင်ဆင်ခြင်း

ကိုယ်စားလှယ် လုပ်ငန်းများကို ထည့်သွင်းရန် သို့မဟုတ် ပြုပြင်ရန် 'commands/code-review.md' ကို ပြင်ဆင်ပါ:
 - လုံခြုံရေး-အာရုံစိုက် ကိုယ်စားလှယ်များကို ထည့်သွင်းပါ
 - စွမ်းဆောင်ရည်ခွဲခြမ်းစိတ်ဖြာရေး ကိုယ်စားလှယ်များကို ထည့်သွင်းပါ
 - လက်လှမ်းမီမှုစစ်ဆေးရေး ကိုယ်စားလှယ်များကို ထည့်သွင်းပါ
 - စာရွက်စာတမ်း အရည်အသွေး စစ်ဆေးမှုများ ထည့်သွင်းပါ

## နည်းပညာဆိုင်ရာ အသေးစိတ်အချက်အလက်များ

### ကိုယ်စားလှယ် ဗိသုကာ
 - **2x CLAUDE.md လိုက်နာမှု ကိုယ်စားလှယ်များ**: လမ်းညွှန်ချက်စစ်ဆေးခြင်းအတွက် ထပ်တိုးခြင်း
 - **1x bug detector**: ပြောင်းလဲမှုများတွင် ထင်ရှားသော bug များကိုသာ အာရုံစိုက်သည်
 - **1x history analyzer**: git blame နှင့် history မှ ဆက်စပ်အခြေအနေ
 - **Nx ယုံကြည်မှု အမှတ်ပေးသူများ**: လွတ်လပ်စွာ အမှတ်ပေးရန်အတွက် ပြဿနာတစ်ခုစီအတွက် တစ်ဦးစီ

### အမှတ်ပေးစနစ်
 - ပြဿနာတစ်ခုချင်းစီကို 0-100 အထိ လွတ်လပ်စွာ အမှတ်ပေးသည်
 - အမှတ်ပေးရာတွင် အထောက်အထားခွန်အားနှင့် အတည်ပြုချက်ကို ထည့်သွင်းစဉ်းစားသည်
 - အမှတ်အသား (ပုံမှန် 80) သည် ယုံကြည်မှုနည်းသော ပြဿနာများကို စစ်ထုတ်သည်
 - CLAUDE.md ပြဿနာများအတွက်: လမ်းညွှန်ချက်တွင် ရှင်းလင်းစွာ ဖော်ပြထားသည်ရှိမရှိ အတည်ပြုသည်

### GitHub ပေါင်းစည်းခြင်း
အောက်ပါတို့အတွက် 'gh' CLI ကို အသုံးပြုသည်:
 - PR အသေးစိတ်အချက်အလက်များနှင့် diff များကို ကြည့်ရှုခြင်း
 - repository data ကို ဆွဲယူခြင်း
 - git blame နှင့် history ကို ဖတ်ခြင်း
 - ပြန်လည်သုံးသပ် comment များကို တင်ခြင်း
