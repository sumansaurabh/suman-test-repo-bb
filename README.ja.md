# コードレビュープラグイン

複数の専門エージェントと信頼度に基づいたスコアリングを使用して、プルリクエストの自動コードレビューを行い、誤検知をフィルタリングします。

## 概要

コードレビュープラグインは、複数のエージェントを並行して起動し、異なる視点から変更を独立して監査することで、プルリクエストのレビューを自動化します。信頼度スコアリングを使用して誤検知をフィルタリングし、高品質で実用的なフィードバックのみが投稿されるようにします。

## コマンド

### '/code-review'

複数の専門エージェントを使用して、プルリクエストに対して自動コードレビューを実行します。

**機能:**
1. レビューが必要かどうかをチェックします（クローズ済み、ドラフト、些細なもの、またはすでにレビュー済みのPRはスキップされます）
2. リポジトリから関連するCLAUDE.mdガイドラインファイルを取得します
3. プルリクエストの変更を要約します
4. 独立してレビューするために4つの並行エージェントを起動します:
   - **エージェント #1 & #2**: CLAUDE.mdへの準拠を監査します
   - **エージェント #3**: 変更における明白なバグをスキャンします
   - **エージェント #4**: コンテキストベースの問題のためにgit blame/履歴を分析します
5. 各問題に信頼度レベル0-100のスコアを付けます
6. 信頼度閾値80を下回る問題をフィルタリングします
7. レビューを出力します（デフォルトではターミナルに、または'--comment'フラグを使用してPRコメントとして）

**使用方法:**
'''bash
/code-review [--comment]
'''

**オプション:**
 - '--comment': レビューをプルリクエストにコメントとして投稿します（デフォルト: ターミナルにのみ出力）

**ワークフロー例:**
'''bash
# PRブランチで、ローカルで実行します（ターミナルに出力されます）:
/code-review

# レビューをPRコメントとして投稿します:
/code-review --comment

# Claudeは以下を実行します:
# - 4つのレビューエージェントを並行して起動します
# - 各問題に信頼度をスコア付けします
# - 信頼度80以上の問題を出力します（フラグに応じてターミナルまたはPRに）
# - 高信頼度の問題が見つからない場合はスキップします
'''

**機能:**
 - 包括的なレビューのための複数の独立したエージェント
 - 信頼度に基づいたスコアリングにより誤検知を削減します（閾値: 80）
 - 明示的なガイドライン検証によるCLAUDE.md準拠チェック
 - 変更に焦点を当てたバグ検出（既存の問題ではない）
 - git blameを介した履歴コンテキスト分析
 - クローズ済み、ドラフト、またはすでにレビュー済みのPRの自動スキップ
 - 完全なSHAと行範囲でコードに直接リンク

**レビューコメント形式:**
'''markdown
## コードレビュー

3つの問題が見つかりました:

1. OAuthコールバックのAエラー処理の欠如 (CLAUDE.mdではOAuthエラーを常に処理するべきと記載されています)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. メモリリーク: OAuthの状態がクリーンアップされていない (finallyブロックでのクリーンアップ不足によるバグ)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. 命名パターンの一貫性がない (src/conventions/CLAUDE.mdでは関数にはcamelCaseを使用するべきと記載されています)

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**信頼度スコアリング:**
 - **0**: 自信なし、誤検知
 - **25**: やや自信あり、本物かもしれない
 - **50**: 中程度の自信あり、本物だが軽微
 - **75**: 高い自信あり、本物で重要
 - **100**: 絶対確実、間違いなく本物

**フィルタリングされた誤検知:**
 - PRで導入されていない既存の問題
 - バグのように見えるがそうではないコード
 - 細かすぎる指摘
 - リンターがキャッチする問題
 - 一般的な品質問題（CLAUDE.mdに記載されている場合を除く）
 - lint ignoreコメント付きの問題

## インストール

このプラグインはClaude Codeリポジトリに含まれています。Claude Codeを使用すると、コマンドが自動的に利用可能になります。

## ベストプラクティス

### '/code-review'の使用
 - より良い準拠チェックのために明確なCLAUDE.mdファイルを維持する
 - 信頼度閾値80以上を信頼する - 誤検知はフィルタリングされます
 - すべての些細ではないプルリクエストで実行する
 - 人間によるレビューの出発点としてエージェントの発見をレビューする
 - 繰り返しのレビューパターンに基づいてCLAUDE.mdを更新する

### 使用すべき場合
 - 意味のある変更を含むすべてのプルリクエスト
 - 重要なコードパスに触れるPR
 - 複数の貢献者からのPR
 - ガイドラインへの準拠が重要なPR

### 使用すべきでない場合
 - クローズ済みまたはドラフトのPR（いずれにせよ自動的にスキップされます）
 - 些細な自動化されたPR（自動的にスキップされます）
 - 即時マージが必要な緊急ホットフィックス
 - すでにレビュー済みのPR（自動的にスキップされます）

## ワークフロー統合

### 標準PRレビューワークフロー:
'''bash
# 変更を含むPRを作成
# ローカルレビューを実行（ターミナルに出力）
/code-review

# 自動フィードバックをレビュー
# 必要な修正を行う

# 必要に応じてPRコメントとして投稿
/code-review --comment

# 準備ができたらマージ
'''

### CI/CDの一部として:
'''bash
# PRの作成または更新時にトリガー
# --commentフラグを使用してレビューコメントを投稿
/code-review --comment
# すでにレビューが存在する場合はスキップ
'''

## 要件

 - GitHub統合を備えたGitリポジトリ
 - GitHub CLI ('gh') がインストールされ、認証済みであること
 - CLAUDE.mdファイル（オプションですが、ガイドラインチェックには推奨）

## トラブルシューティング

### レビューに時間がかかりすぎる

**問題**: エージェントが大規模なPRで遅い

**解決策**:
 - 大規模な変更では通常のことです - エージェントは並行して実行されます
 - 4つの独立したエージェントが徹底性を保証します
 - 大規模なPRを小さなものに分割することを検討してください

### 誤検知が多すぎる

**問題**: レビューが実際には問題ではないものをフラグする

**解決策**:
 - デフォルトの閾値は80です（すでにほとんどの誤検知をフィルタリングしています）
 - 重要なことについてCLAUDE.mdをより具体的にする
 - フラグされた問題が実際に有効であるかどうかを検討する

### レビューコメントが投稿されない

**問題**: '/code-review'は実行されるが、コメントが表示されない

**解決策**:
以下をチェックしてください:
 - PRがクローズされている（レビューはスキップされます）
 - PRがドラフトである（レビューはスキップされます）
 - PRが些細なもの/自動化されている（レビューはスキップされます）
 - PRがすでにレビューされている（レビューはスキップされます）
 - 80以上のスコアの問題がない（コメントは不要）

### リンクのフォーマットが壊れている

**問題**: GitHubでコードリンクが正しくレンダリングされない

**解決策**:
リンクは次の正確な形式に従う必要があります:
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - 完全なSHAを使用する必要があります（省略形ではない）
 - '#L'表記を使用する必要があります
 - 少なくとも1行のコンテキストを含む行範囲を含める必要があります

### GitHub CLIが機能しない

**問題**: 'gh'コマンドが失敗する

**解決策**:
 - GitHub CLIをインストールする: 'brew install gh' (macOS) または[GitHub CLIのインストール](https://cli.github.com/)を参照
 - 認証する: 'gh auth login'
 - リポジトリにGitHubリモートがあることを確認する

## ヒント

 - **具体的なCLAUDE.mdファイルを作成する**: 明確なガイドライン = より良いレビュー
 - **PRにコンテキストを含める**: エージェントが意図を理解するのに役立ちます
 - **信頼度スコアを使用する**: 80以上の問題は通常正しいです
 - **ガイドラインを反復する**: パターンに基づいてCLAUDE.mdを更新する
 - **自動的にレビューする**: PRワークフローの一部として設定する
 - **フィルタリングを信頼する**: 閾値はノイズを防ぎます

## 設定

### 信頼度閾値の調整

デフォルトの閾値は80です。調整するには、'commands/code-review.md'のコマンドファイルを変更します:
'''markdown
スコアが80未満の問題をすべてフィルタリングします。
'''

'80'を好みの閾値（0-100）に変更します。

### レビューの焦点をカスタマイズする

エージェントタスクを追加または変更するには、'commands/code-review.md'を編集します:
 - セキュリティに焦点を当てたエージェントを追加する
 - パフォーマンス分析エージェントを追加する
 - アクセシビリティチェックエージェントを追加する
 - ドキュメント品質チェックを追加する

## 技術詳細

### エージェントアーキテクチャ
 - **2x CLAUDE.md準拠エージェント**: ガイドラインチェックの冗長性
 - **1x バグ検出器**: 変更における明白なバグのみに焦点を当てる
 - **1x 履歴アナライザー**: git blameと履歴からのコンテキスト
 - **Nx 信頼度スコアラー**: 独立したスコアリングのための問題ごとに1つ

### スコアリングシステム
 - 各問題は0-100で独立してスコア付けされます
 - スコアリングは証拠の強さと検証を考慮します
 - 閾値（デフォルト80）は信頼度の低い問題をフィルタリングします
 - CLAUDE.mdの問題の場合: ガイドラインがそれを明示的に言及していることを検証します

### GitHub統合
'gh' CLIを使用して以下を実行します:
 - PRの詳細と差分を表示する
 - リポジトリデータをフェッチする
 - git blameと履歴を読み取る
 - レビューコメントを投稿する
