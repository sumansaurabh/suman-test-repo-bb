# コードレビュープラグイン

複数の専門エージェントと信頼度に基づいたスコアリングを使用して、プルリクエストの自動コードレビューを行い、誤検知をフィルタリングします。

## 概要

コードレビュープラグインは、複数のエージェントを並行して起動し、さまざまな視点から変更を独立して監査することで、プルリクエストのレビューを自動化します。信頼度スコアリングを使用して誤検知をフィルタリングし、高品質で実行可能なフィードバックのみが投稿されるようにします。

## コマンド

### '/code-review'

複数の専門エージェントを使用して、プルリクエストの自動コードレビューを実行します。

**機能：**
1. レビューが必要かどうかを確認します（クローズ済み、ドラフト、軽微なPR、またはすでにレビュー済みのPRはスキップされます）
2. リポジトリから関連する CLAUDE.md ガイドラインファイルを取得します
3. プルリクエストの変更点を要約します
4. 独立してレビューするために4つの並行エージェントを起動します：
   - **エージェント #1 & #2**：CLAUDE.md 準拠の監査
   - **エージェント #3**：変更点に明らかなバグがないかスキャンします
   - **エージェント #4**：コンテキストに基づいた問題のために git blame/履歴を分析します
5. 各問題の信頼度レベルを0-100でスコアリングします
6. 信頼度しきい値80未満の問題をフィルタリングします
7. レビューを出力します（デフォルトではターミナルに出力、または '--comment' フラグでPRコメントとして出力）

**使用方法：**
'''bash
/code-review [--comment]
'''

**オプション：**
 - '--comment'：レビューをプルリクエストのコメントとして投稿します（デフォルト：ターミナルにのみ出力）

**ワークフロー例：**
'''bash
# PRブランチでローカルで実行します（ターミナルに出力）：
/code-review

# レビューをPRコメントとして投稿します：
/code-review --comment

# Claudeは次のことを行います：
# - 4つのレビューエージェントを並行して起動します
# - 各問題の信頼度をスコアリングします
# - 信頼度が80以上の問題を出力します（フラグに応じてターミナルまたはPRに）
# - 高信頼度の問題が見つからない場合はスキップします
'''

**特徴：**
 - 包括的なレビューのための複数の独立したエージェント
 - 信頼度に基づいたスコアリングにより誤検知を削減（しきい値：80）
 - 明示的なガイドライン検証による CLAUDE.md 準拠チェック
 - 変更点に焦点を当てたバグ検出（既存の問題ではなく）
 - git blame を介した履歴コンテキスト分析
 - クローズ済み、ドラフト、またはすでにレビュー済みのPRの自動スキップ
 - 完全なSHAと行範囲を含むコードへの直接リンク

**レビューコメント形式：**
'''markdown
## コードレビュー

3つの問題が見つかりました：

1. OAuthコールバックのエラー処理が不足しています（CLAUDE.mdには「OAuthエラーを常に処理する」と記載されています）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. メモリリーク：OAuthの状態がクリーンアップされていません（finallyブロックでのクリーンアップ不足によるバグ）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. 一貫性のない命名パターン（src/conventions/CLAUDE.mdには「関数にはcamelCaseを使用する」と記載されています）

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**信頼度スコアリング：**
 - **0**：信頼できない、誤検知
 - **25**：やや信頼できる、実際に存在する可能性がある
 - **50**：中程度に信頼できる、実際に存在するが軽微な問題
 - **75**：非常に信頼できる、実際に存在し重要な問題
 - **100**：絶対に確実、間違いなく存在する問題

**フィルタリングされた誤検知：**
 - PRで導入されていない既存の問題
 - バグのように見えるが実際にはそうではないコード
 - 厳密すぎる指摘
 - リンターが検出する問題
 - 一般的な品質問題（CLAUDE.mdに記載がない限り）
 - リンター無視コメントのある問題

## インストール

このプラグインはClaude Codeリポジトリに含まれています。Claude Codeを使用する場合、コマンドは自動的に利用可能になります。

## ベストプラクティス

### '/code-review' の使用
 - より良い準拠チェックのために明確な CLAUDE.md ファイルを維持します
 - 80+の信頼度しきい値を信頼します - 誤検知はフィルタリングされます
 - すべての軽微でないプルリクエストで実行します
 - 人間によるレビューの出発点としてエージェントの調査結果を確認します
 - 必要な修正を行います
 - 必要に応じてPRコメントとして投稿します
 - 準備ができたらマージします
 - 繰り返しのレビューパターンに基づいて CLAUDE.md を更新します

### 使用するタイミング
 - 意味のある変更を含むすべてのプルリクエスト
 - 重要なコードパスに触れるPR
 - 複数の貢献者からのPR
 - ガイドライン準拠が重要なPR

### 使用しないタイミング
 - クローズ済みまたはドラフトのPR（自動的にスキップされます）
 - 軽微な自動PR（自動的にスキップされます）
 - 緊急のホットフィックスで即時マージが必要な場合
 - すでにレビュー済みのPR（自動的にスキップされます）

## ワークフロー統合

### 標準のPRレビューワークフロー：
'''bash
# 変更を含むPRを作成します
# ローカルでレビューを実行します（ターミナルに出力）
/code-review

# 自動フィードバックを確認します
# 必要な修正を行います

# 必要に応じてPRコメントとして投稿します
/code-review --comment

# 準備ができたらマージします
'''

### CI/CDの一部として：
'''bash
# PRの作成または更新時にトリガーします
# レビューコメントを投稿するために --comment フラグを使用します
/code-review --comment
# レビューがすでに存在する場合はスキップします
'''

## 要件

 - GitHub統合を備えたGitリポジトリ
 - GitHub CLI ('gh') がインストールされ、認証されていること
 - CLAUDE.md ファイル（オプションですが、ガイドラインチェックには推奨されます）

## トラブルシューティング

### レビューに時間がかかりすぎる

**問題**：エージェントは大規模なPRで遅くなります

**解決策**：
 - 大規模な変更では正常です - エージェントは並行して実行されます
 - 4つの独立したエージェントが徹底的なレビューを保証します
 - 大規模なPRを小さなものに分割することを検討してください

### 誤検知が多すぎる

**問題**：レビューが実際にはそうではない問題を指摘します

**解決策**：
 - デフォルトのしきい値は80です（すでにほとんどの誤検知をフィルタリングしています）
 - CLAUDE.md で何が重要かをもっと具体的にします
 - 指摘された問題が実際に有効かどうかを検討します

### レビューコメントが投稿されない

**問題**：'/code-review' は実行されるが、コメントが表示されない

**解決策**：
以下を確認してください：
 - PRがクローズされている（レビューはスキップされます）
 - PRがドラフトである（レビューはスキップされます）
 - PRが軽微/自動である（レビューはスキップされます）
 - PRがすでにレビュー済みである（レビューはスキップされます）
 - 80以上のスコアの問題がない（コメントは不要です）

### リンク形式が壊れている

**問題**：GitHubでコードリンクが正しくレンダリングされない

**解決策**：
リンクは以下の正確な形式に従う必要があります：
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - 完全なSHAを使用する必要があります（省略形ではありません）
 - '#L'表記を使用する必要があります
 - 少なくとも1行のコンテキストを含む行範囲を含める必要があります

### GitHub CLIが動作しない

**問題**：'gh'コマンドが失敗します

**解決策**：
 - GitHub CLIをインストールします：'brew install gh' (macOS) または [GitHub CLIのインストール](https://cli.github.com/) を参照してください
 - 認証します：'gh auth login'
 - リポジトリにGitHubリモートがあることを確認します

## ヒント

 - **具体的な CLAUDE.md ファイルを作成する**：明確なガイドライン = より良いレビュー
 - **PRにコンテキストを含める**：エージェントが意図を理解するのに役立ちます
 - **信頼度スコアを使用する**：80以上の問題は通常正しいです
 - **ガイドラインを繰り返す**：パターンに基づいて CLAUDE.md を更新します
 - **自動的にレビューする**：PRワークフローの一部として設定します
 - **フィルタリングを信頼する**：しきい値はノイズを防ぎます

## 技術詳細

### エージェントアーキテクチャ
 - **2x CLAUDE.md 準拠エージェント**：ガイドラインチェックの冗長性
 - **1x バグ検出器**：変更点における明らかなバグにのみ焦点を当てます
 - **1x 履歴分析器**：git blame と履歴からのコンテキスト
 - **Nx 信頼度スコアラー**：独立したスコアリングのために問題ごとに1つ

### スコアリングシステム
 - 各問題は0-100で独立してスコアリングされます
 - スコアリングは証拠の強さと検証を考慮します
 - しきい値（デフォルト80）は低信頼度の問題をフィルタリングします
 - CLAUDE.md の問題の場合：ガイドラインが明示的に言及していることを確認します

### GitHub統合
'gh' CLI を使用して以下を行います：
 - PRの詳細と差分を表示します
 - リポジトリデータを取得します
 - git blame と履歴を読み取ります
 - レビューコメントを投稿します
