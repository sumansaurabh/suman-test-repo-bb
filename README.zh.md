# 代码审查插件

使用多个专业代理进行拉取请求的自动化代码审查，通过基于置信度的评分来过滤误报。

## 概述

代码审查插件通过并行启动多个代理，从不同角度独立审计变更，从而实现拉取请求的自动化审查。它使用置信度评分来过滤掉误报，确保只发布高质量、可操作的反馈。

## 命令

### '/code-review'

使用多个专业代理对拉取请求执行自动化代码审查。

**功能：**
1. 检查是否需要审查（跳过已关闭、草稿、琐碎或已审查的拉取请求）
2. 从仓库中收集相关的 CLAUDE.md 指南文件
3. 总结拉取请求的变更
4. 启动 4 个并行代理独立审查：
   - **代理 #1 和 #2**：审计 CLAUDE.md 合规性
   - **代理 #3**：扫描变更中的明显错误
   - **代理 #4**：分析 git blame/历史记录以获取基于上下文的问题
5. 为每个问题评分 0-100 的置信度
6. 过滤掉低于 80 置信度阈值的问题
7. 输出审查结果（默认输出到终端，或使用 '--comment' 标志作为拉取请求评论）

**用法：**
'''bash
/code-review [--comment]
'''

**选项：**
 - '--comment'：将审查结果作为评论发布到拉取请求（默认：仅输出到终端）

**示例工作流程：**
'''bash
# 在拉取请求分支上，本地运行（输出到终端）：
/code-review

# 将审查结果作为拉取请求评论发布：
/code-review --comment

# Claude 将：
# - 并行启动 4 个审查代理
# - 为每个问题评分置信度
# - 输出置信度 ≥80 的问题（根据标志输出到终端或拉取请求）
# - 如果没有发现高置信度问题则跳过
'''

**功能：**
 - 多个独立代理进行全面审查
 - 基于置信度的评分减少误报（阈值：80）
 - CLAUDE.md 合规性检查，并进行明确的指南验证
 - 专注于变更的错误检测（而非预先存在的问题）
 - 通过 git blame 进行历史上下文分析
 - 自动跳过已关闭、草稿或已审查的拉取请求
 - 直接链接到带有完整 SHA 和行范围的代码

**审查评论格式：**
'''markdown
## 代码审查

发现 3 个问题：

1. OAuth 回调缺少错误处理（CLAUDE.md 指出始终处理 OAuth 错误）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. 内存泄漏：OAuth 状态未清理（由于 finally 块中缺少清理导致的错误）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. 命名模式不一致（src/conventions/CLAUDE.md 指出函数使用 camelCase）

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**置信度评分：**
 - **0**：不自信，误报
 - **25**：有点自信，可能是真的
 - **50**：中等自信，是真的但次要
 - **75**：高度自信，是真的且重要
 - **100**：绝对确定，肯定是真的

**已过滤的误报：**
 - 拉取请求中未引入的预先存在的问题
 - 看起来像错误但不是的代码
 - 吹毛求疵的细节
 - Linter 会捕获的问题
 - 一般质量问题（除非在 CLAUDE.md 中提及）
 - 带有 lint ignore 注释的问题

## 安装

此插件包含在 Claude Code 仓库中。使用 Claude Code 时，该命令自动可用。

## 最佳实践

### 使用 '/code-review'
 - 维护清晰的 CLAUDE.md 文件以获得更好的合规性检查
 - 信任 80+ 的置信度阈值 - 误报会被过滤
 - 在所有非琐碎的拉取请求上运行
 - 将代理发现作为人工审查的起点
 - 根据重复的审查模式更新 CLAUDE.md

### 何时使用
 - 所有有意义变更的拉取请求
 - 涉及关键代码路径的拉取请求
 - 来自多个贡献者的拉取请求
 - 合规性很重要的拉取请求

### 何时不使用
 - 已关闭或草稿拉取请求（无论如何都会自动跳过）
 - 琐碎的自动化拉取请求（自动跳过）
 - 需要立即合并的紧急热修复
 - 已审查的拉取请求（自动跳过）

## 工作流程集成

### 标准拉取请求审查工作流程：
'''bash
# 创建带有变更的拉取请求
# 运行本地审查（输出到终端）
/code-review

# 审查自动化反馈
# 进行任何必要的修复

# 可选地作为拉取请求评论发布
/code-review --comment

# 准备好后合并
'''

### 作为 CI/CD 的一部分：
'''bash
# 在拉取请求创建或更新时触发
# 使用 --comment 标志发布审查评论
/code-review --comment
# 如果审查已存在则跳过
'''

## 要求

 - 带有 GitHub 集成的 Git 仓库
 - 已安装并认证的 GitHub CLI ('gh')
 - CLAUDE.md 文件（可选，但建议用于指南检查）

## 故障排除

### 审查时间过长

**问题**：代理在大型拉取请求上运行缓慢

**解决方案**：
 - 对于大型变更来说是正常的 - 代理并行运行
 - 4 个独立代理确保彻底性
 - 考虑将大型拉取请求拆分为较小的拉取请求

### 误报过多

**问题**：审查标记了不真实的问题

**解决方案**：
 - 默认阈值为 80（已过滤大部分误报）
 - 使 CLAUDE.md 更具体地说明重要内容
 - 考虑被标记的问题是否确实有效

### 未发布审查评论

**问题**：'/code-review' 运行但未出现评论

**解决方案**：
检查是否：
 - 拉取请求已关闭（跳过审查）
 - 拉取请求是草稿（跳过审查）
 - 拉取请求是琐碎/自动化的（跳过审查）
 - 拉取请求已有审查（跳过审查）
 - 没有问题得分 ≥80（无需评论）

### 链接格式损坏

**问题**：代码链接在 GitHub 中无法正确渲染

**解决方案**：
链接必须遵循以下确切格式：
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - 必须使用完整的 SHA（而非缩写）
 - 必须使用 '#L' 符号
 - 必须包含至少 1 行上下文的行范围

### GitHub CLI 不工作

**问题**：'gh' 命令失败

**解决方案**：
 - 安装 GitHub CLI：'brew install gh' (macOS) 或参阅 [GitHub CLI 安装](https://cli.github.com/)
 - 认证：'gh auth login'
 - 验证仓库是否具有 GitHub 远程

## 提示

 - **编写具体的 CLAUDE.md 文件**：清晰的指南 = 更好的审查
 - **在拉取请求中包含上下文**：帮助代理理解意图
 - **使用置信度评分**：≥80 的问题通常是正确的
 - **迭代指南**：根据模式更新 CLAUDE.md
 - **自动审查**：设置为拉取请求工作流程的一部分
 - **信任过滤**：阈值可防止噪音

## 配置

### 调整置信度阈值

默认阈值为 80。要调整，请修改 'commands/code-review.md' 中的命令文件：
'''markdown
过滤掉任何得分低于 80 的问题。
'''

将 '80' 更改为您偏好的阈值（0-100）。

### 自定义审查重点

编辑 'commands/code-review.md' 以添加或修改代理任务：
 - 添加专注于安全的代理
 - 添加性能分析代理
 - 添加可访问性检查代理
 - 添加文档质量检查

## 技术细节

### 代理架构
 - **2x CLAUDE.md 合规性代理**：指南检查的冗余
 - **1x 错误检测器**：仅专注于变更中的明显错误
 - **1x 历史分析器**：来自 git blame 和历史记录的上下文
 - **Nx 置信度评分器**：每个问题一个，用于独立评分

### 评分系统
 - 每个问题独立评分 0-100
 - 评分考虑证据强度和验证
 - 阈值（默认 80）过滤低置信度问题
 - 对于 CLAUDE.md 问题：明确验证指南中是否提及

### GitHub 集成
使用 'gh' CLI 进行：
 - 查看拉取请求详细信息和差异
 - 获取仓库数据
 - 读取 git blame 和历史记录
 - 发布审查评论
