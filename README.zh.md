# 代码审查插件

使用多个专业代理进行拉取请求的自动化代码审查，通过基于置信度的评分来过滤误报。

## 概述

代码审查插件通过并行启动多个代理，从不同角度独立审计更改，从而自动化拉取请求审查。它使用置信度评分来过滤误报，确保只发布高质量、可操作的反馈。

## 命令

### '/code-review'

使用多个专业代理对拉取请求执行自动化代码审查。

**它的作用：**
1. 检查是否需要审查（跳过已关闭、草稿、琐碎或已审查的 PR）
2. 从仓库中收集相关的 CLAUDE.md 指南文件
3. 总结拉取请求的更改
4. 启动 4 个并行代理独立审查：
   - **代理 #1 和 #2**：审计 CLAUDE.md 合规性
   - **代理 #3**：扫描更改中的明显错误
   - **代理 #4**：分析 git blame/历史记录以获取基于上下文的问题
5. 为每个问题的置信度级别打分 0-100
6. 过滤掉低于 80 置信度阈值的问题
7. 输出审查结果（默认输出到终端，或使用 '--comment' 标志作为 PR 评论）

**用法：**
'''bash
/code-review [--comment]
'''

**选项：**
 - '--comment'：将审查结果作为评论发布到拉取请求（默认：仅输出到终端）

**工作流程示例：**
'''bash
# 在 PR 分支上，本地运行（输出到终端）：
/code-review

# 将审查结果作为 PR 评论发布：
/code-review --comment

# Claude 将：
# - 并行启动 4 个审查代理
# - 为每个问题的置信度打分
# - 输出置信度 ≥80 的问题（根据标志输出到终端或 PR）
# - 如果没有发现高置信度问题则跳过
'''

**特点：**
 - 多个独立代理进行全面审查
 - 基于置信度的评分减少误报（阈值：80）
 - 通过明确的指南验证进行 CLAUDE.md 合规性检查
 - 专注于更改中的错误检测（而非预先存在的问题）
 - 通过 git blame 进行历史上下文分析
 - 自动跳过已关闭、草稿或已审查的 PR
 - 直接链接到具有完整 SHA 和行范围的代码

**审查评论格式：**
'''markdown
## 代码审查

发现 3 个问题：

1. OAuth 回调缺少错误处理（CLAUDE.md 指出“始终处理 OAuth 错误”）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. 内存泄漏：OAuth 状态未清理（由于 finally 块中缺少清理导致的错误）

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. 命名模式不一致（src/conventions/CLAUDE.md 指出“函数使用 camelCase”）

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**置信度评分：**
 - **0**：不自信，误报
 - **25**：有点自信，可能是真的
 - **50**：中等自信，是真的但很小
 - **75**：高度自信，是真的且重要
 - **100**：绝对确定，肯定是真的

**过滤掉的误报：**
 - PR 中未引入的预先存在的问题
 - 看起来像错误但不是的代码
 - 吹毛求疵
 - Linter 会捕获的问题
 - 一般质量问题（除非在 CLAUDE.md 中提及）
 - 带有 lint 忽略注释的问题

## 安装

此插件包含在 Claude Code 仓库中。使用 Claude Code 时，该命令自动可用。

## 最佳实践

### 使用 '/code-review'
 - 维护清晰的 CLAUDE.md 文件以进行更好的合规性检查
 - 信任 80+ 的置信度阈值 - 误报会被过滤
 - 在所有非琐碎的拉取请求上运行
 - 将代理发现作为人工审查的起点
 - 进行任何必要的修复
 - 可选择作为 PR 评论发布
 - 准备好后合并
 - 根据重复的审查模式更新 CLAUDE.md

### 何时使用
 - 所有具有有意义更改的拉取请求
 - 涉及关键代码路径的 PR
 - 来自多个贡献者的 PR
 - 关注指南合规性的 PR

### 何时不使用
 - 已关闭或草稿的 PR（反正会自动跳过）
 - 琐碎的自动化 PR（会自动跳过）
 - 需要立即合并的紧急热修复
 - 已审查的 PR（会自动跳过）

## 工作流程集成

### 标准 PR 审查工作流程：
'''bash
# 创建带有更改的 PR
# 运行本地审查（输出到终端）
/code-review

# 审查自动化反馈
# 进行任何必要的修复

# 可选择作为 PR 评论发布
/code-review --comment

# 准备好后合并
'''

### 作为 CI/CD 的一部分：
'''bash
# 在 PR 创建或更新时触发
# 使用 --comment 标志发布审查评论
/code-review --comment
# 如果审查已存在则跳过
'''

## 要求

 - 具有 GitHub 集成的 Git 仓库
 - 已安装并认证 GitHub CLI ('gh')
 - CLAUDE.md 文件（可选，但建议用于指南检查）

## 故障排除

### 审查时间过长

**问题**：代理在大型 PR 上运行缓慢

**解决方案**：
 - 对于大型更改来说是正常的 - 代理并行运行
 - 4 个独立代理确保彻底性
 - 考虑将大型 PR 拆分为较小的 PR

### 误报过多

**问题**：审查标记了并非真实的问题

**解决方案**：
 - 默认阈值为 80（已过滤掉大多数误报）
 - 使 CLAUDE.md 更具体地说明什么才是重要的
 - 考虑被标记的问题是否确实有效

### 未发布审查评论

**问题**：'/code-review' 运行但未显示评论

**解决方案**：
检查是否：
 - PR 已关闭（审查已跳过）
 - PR 是草稿（审查已跳过）
 - PR 是琐碎/自动的（审查已跳过）
 - PR 已有审查（审查已跳过）
 - 没有问题得分 ≥80（不需要评论）

### 链接格式损坏

**问题**：GitHub 中代码链接显示不正确

**解决方案**：
链接必须遵循以下精确格式：
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - 必须使用完整的 SHA（而非缩写）
 - 必须使用 '#L' 符号
 - 必须包含至少 1 行上下文的行范围

### GitHub CLI 不工作

**问题**：'gh' 命令失败

**解决方案**：
 - 安装 GitHub CLI：'brew install gh' (macOS) 或参阅 [GitHub CLI 安装](https://cli.github.com/)
 - 认证：'gh auth login'
 - 验证仓库是否具有 GitHub 远程

## 提示

 - **编写具体的 CLAUDE.md 文件**：清晰的指南 = 更好的审查
 - **在 PR 中包含上下文**：帮助代理理解意图
 - **使用置信度评分**：≥80 的问题通常是正确的
 - **迭代指南**：根据模式更新 CLAUDE.md
 - **自动审查**：设置为 PR 工作流程的一部分
 - **信任过滤**：阈值防止噪音

## 技术细节

### 代理架构
 - **2x CLAUDE.md 合规性代理**：用于指南检查的冗余
 - **1x 错误检测器**：仅专注于更改中的明显错误
 - **1x 历史分析器**：来自 git blame 和历史记录的上下文
 - **Nx 置信度评分器**：每个问题一个，用于独立评分

### 评分系统
 - 每个问题独立评分 0-100
 - 评分考虑证据强度和验证
 - 阈值（默认 80）过滤掉低置信度问题
 - 对于 CLAUDE.md 问题：验证指南是否明确提及

### GitHub 集成
使用 'gh' CLI 进行：
 - 查看 PR 详细信息和差异
 - 获取仓库数据
 - 读取 git blame 和历史记录
 - 发布审查评论
