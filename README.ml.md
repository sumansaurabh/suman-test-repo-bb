# കോഡ് റിവ്യൂ പ്ലഗിൻ

തെറ്റായ പോസിറ്റീവുകൾ ഫിൽട്ടർ ചെയ്യുന്നതിനായി കോൺഫിഡൻസ് അടിസ്ഥാനമാക്കിയുള്ള സ്കോറിംഗ് ഉപയോഗിച്ച് ഒന്നിലധികം സ്പെഷ്യലൈസ്ഡ് ഏജൻ്റുമാരെ ഉപയോഗിച്ച് പുൾ അഭ്യർത്ഥനകൾക്കായി ഓട്ടോമേറ്റഡ് കോഡ് അവലോകനം.

## അവലോകനം

കോഡ് റിവ്യൂ പ്ലഗിൻ, പുൾ അഭ്യർത്ഥന അവലോകനം ഓട്ടോമേറ്റ് ചെയ്യുന്നു. ഇതിനായി ഒന്നിലധികം ഏജൻ്റുമാരെ സമാന്തരമായി പ്രവർത്തിപ്പിച്ച് വിവിധ വീക്ഷണകോണുകളിൽ നിന്ന് മാറ്റങ്ങൾ സ്വതന്ത്രമായി ഓഡിറ്റ് ചെയ്യുന്നു. തെറ്റായ പോസിറ്റീവുകൾ ഫിൽട്ടർ ചെയ്യുന്നതിനായി ഇത് കോൺഫിഡൻസ് സ്കോറിംഗ് ഉപയോഗിക്കുന്നു, ഉയർന്ന നിലവാരമുള്ളതും പ്രവർത്തനക്ഷമവുമായ ഫീഡ്‌ബാക്ക് മാത്രമേ പോസ്റ്റ് ചെയ്യുന്നുള്ളൂ എന്ന് ഉറപ്പാക്കുന്നു.

## കമാൻഡുകൾ

### '/code-review'

ഒന്നിലധികം സ്പെഷ്യലൈസ്ഡ് ഏജൻ്റുമാരെ ഉപയോഗിച്ച് ഒരു പുൾ അഭ്യർത്ഥനയിൽ ഓട്ടോമേറ്റഡ് കോഡ് അവലോകനം നടത്തുന്നു.

**ഇത് ചെയ്യുന്ന കാര്യങ്ങൾ:**
1. അവലോകനം ആവശ്യമുണ്ടോ എന്ന് പരിശോധിക്കുന്നു (അടച്ച, ഡ്രാഫ്റ്റ്, നിസ്സാരമായ, അല്ലെങ്കിൽ ഇതിനകം അവലോകനം ചെയ്ത PR-കൾ ഒഴിവാക്കുന്നു)
2. റിപ്പോസിറ്ററിയിൽ നിന്ന് പ്രസക്തമായ CLAUDE.md മാർഗ്ഗനിർദ്ദേശ ഫയലുകൾ ശേഖരിക്കുന്നു
3. പുൾ അഭ്യർത്ഥനയിലെ മാറ്റങ്ങൾ സംഗ്രഹിക്കുന്നു
4. സ്വതന്ത്രമായി അവലോകനം ചെയ്യാൻ 4 സമാന്തര ഏജൻ്റുമാരെ പ്രവർത്തിപ്പിക്കുന്നു:
   - **ഏജൻ്റ് #1 & #2**: CLAUDE.md പാലിക്കുന്നുണ്ടോ എന്ന് ഓഡിറ്റ് ചെയ്യുന്നു
   - **ഏജൻ്റ് #3**: മാറ്റങ്ങളിലെ വ്യക്തമായ ബഗുകൾക്കായി സ്കാൻ ചെയ്യുന്നു
   - **ഏജൻ്റ് #4**: സന്ദർഭത്തെ അടിസ്ഥാനമാക്കിയുള്ള പ്രശ്നങ്ങൾക്കായി git blame/history വിശകലനം ചെയ്യുന്നു
5. ഓരോ പ്രശ്നത്തിനും 0-100 വരെ കോൺഫിഡൻസ് ലെവൽ സ്കോർ ചെയ്യുന്നു
6. 80 കോൺഫിഡൻസ് പരിധിക്ക് താഴെയുള്ള പ്രശ്നങ്ങൾ ഫിൽട്ടർ ചെയ്യുന്നു
7. അവലോകനം ഔട്ട്പുട്ട് ചെയ്യുന്നു (സ്ഥിരസ്ഥിതിയായി ടെർമിനലിലേക്ക്, അല്ലെങ്കിൽ '--comment' ഫ്ലാഗ് ഉപയോഗിച്ച് PR കമൻ്റായി)

**ഉപയോഗം:**
'''bash
/code-review [--comment]
'''

**ഓപ്ഷനുകൾ:**
 - '--comment': അവലോകനം പുൾ അഭ്യർത്ഥനയിൽ ഒരു കമൻ്റായി പോസ്റ്റ് ചെയ്യുക (സ്ഥിരസ്ഥിതി: ടെർമിനലിലേക്ക് മാത്രം ഔട്ട്പുട്ട് ചെയ്യുന്നു)

**ഉദാഹരണ വർക്ക്ഫ്ലോ:**
'''bash
# ഒരു PR ബ്രാഞ്ചിൽ, പ്രാദേശികമായി പ്രവർത്തിപ്പിക്കുക (ടെർമിനലിലേക്ക് ഔട്ട്പുട്ട് ചെയ്യുന്നു):
/code-review

# PR കമൻ്റായി അവലോകനം പോസ്റ്റ് ചെയ്യുക:
/code-review --comment

# Claude ചെയ്യും:
# - 4 അവലോകന ഏജൻ്റുമാരെ സമാന്തരമായി പ്രവർത്തിപ്പിക്കുന്നു
# - ഓരോ പ്രശ്നത്തിനും കോൺഫിഡൻസ് സ്കോർ ചെയ്യുന്നു
# - ≥80 കോൺഫിഡൻസുള്ള പ്രശ്നങ്ങൾ ഔട്ട്പുട്ട് ചെയ്യുന്നു (ഫ്ലാഗ് അനുസരിച്ച് ടെർമിനലിലേക്കോ PR-ലേക്കോ)
# - ഉയർന്ന കോൺഫിഡൻസുള്ള പ്രശ്നങ്ങളൊന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുന്നു
'''

**സവിശേഷതകൾ:**
 - സമഗ്രമായ അവലോകനത്തിനായി ഒന്നിലധികം സ്വതന്ത്ര ഏജൻ്റുമാർ
 - കോൺഫിഡൻസ് അടിസ്ഥാനമാക്കിയുള്ള സ്കോറിംഗ് തെറ്റായ പോസിറ്റീവുകൾ കുറയ്ക്കുന്നു (പരിധി: 80)
 - വ്യക്തമായ മാർഗ്ഗനിർദ്ദേശ പരിശോധനയോടെ CLAUDE.md പാലിക്കുന്നുണ്ടോ എന്ന് പരിശോധിക്കുന്നു
 - മാറ്റങ്ങളിൽ ശ്രദ്ധ കേന്ദ്രീകരിച്ചുള്ള ബഗ് കണ്ടെത്തൽ (നിലവിലുള്ള പ്രശ്നങ്ങളിലല്ല)
 - git blame വഴിയുള്ള ചരിത്രപരമായ സന്ദർഭ വിശകലനം
 - അടച്ച, ഡ്രാഫ്റ്റ്, അല്ലെങ്കിൽ ഇതിനകം അവലോകനം ചെയ്ത PR-കൾ സ്വയമേവ ഒഴിവാക്കുന്നു
 - പൂർണ്ണ SHA, ലൈൻ ശ്രേണികൾ എന്നിവ ഉപയോഗിച്ച് കോഡിലേക്ക് നേരിട്ട് ലിങ്ക് ചെയ്യുന്നു

**അവലോകന കമൻ്റ് ഫോർമാറ്റ്:**
'''markdown
## കോഡ് അവലോകനം

3 പ്രശ്നങ്ങൾ കണ്ടെത്തി:

1. OAuth കോൾബാക്കിനായുള്ള പിശക് കൈകാര്യം ചെയ്യൽ ഇല്ല (CLAUDE.md പറയുന്നത് OAuth പിശകുകൾ എപ്പോഴും കൈകാര്യം ചെയ്യണം എന്നാണ്)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L67-L72

2. മെമ്മറി ലീക്ക്: OAuth സ്റ്റേറ്റ് വൃത്തിയാക്കിയിട്ടില്ല (finally ബ്ലോക്കിൽ ക്ലീനപ്പ് ഇല്ലാത്തതുകൊണ്ടുള്ള ബഗ്)

https://github.com/owner/repo/blob/abc123.../src/auth.ts#L88-L95

3. സ്ഥിരതയില്ലാത്ത പേരിടൽ രീതി (src/conventions/CLAUDE.md പറയുന്നത് ഫംഗ്ഷനുകൾക്ക് camelCase ഉപയോഗിക്കണം എന്നാണ്)

https://github.com/owner/repo/blob/abc123.../src/utils.ts#L23-L28
'''

**കോൺഫിഡൻസ് സ്കോറിംഗ്:**
 - **0**: കോൺഫിഡൻസ് ഇല്ല, തെറ്റായ പോസിറ്റീവ്
 - **25**: ഒരു പരിധി വരെ കോൺഫിഡൻസ് ഉണ്ട്, യഥാർത്ഥമായിരിക്കാം
 - **50**: മിതമായ കോൺഫിഡൻസ് ഉണ്ട്, യഥാർത്ഥമാണ് എന്നാൽ ചെറുതാണ്
 - **75**: ഉയർന്ന കോൺഫിഡൻസ് ഉണ്ട്, യഥാർത്ഥവും പ്രധാനപ്പെട്ടതുമാണ്
 - **100**: തീർത്തും ഉറപ്പാണ്, തീർച്ചയായും യഥാർത്ഥമാണ്

**ഫിൽട്ടർ ചെയ്ത തെറ്റായ പോസിറ്റീവുകൾ:**
 - PR-ൽ അവതരിപ്പിക്കാത്ത നിലവിലുള്ള പ്രശ്നങ്ങൾ
 - ബഗ് പോലെ തോന്നിക്കുന്ന എന്നാൽ അല്ലാത്ത കോഡ്
 - അനാവശ്യമായ നിറ്റ്പിക്കുകൾ
 - ലിൻ്ററുകൾ കണ്ടെത്തുന്ന പ്രശ്നങ്ങൾ
 - പൊതുവായ ഗുണനിലവാര പ്രശ്നങ്ങൾ (CLAUDE.md-ൽ ഇല്ലെങ്കിൽ)
 - ലിൻ്റ് അവഗണിക്കുന്ന കമൻ്റുകളുള്ള പ്രശ്നങ്ങൾ

## ഇൻസ്റ്റാളേഷൻ

ഈ പ്ലഗിൻ Claude Code റിപ്പോസിറ്ററിയിൽ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്. Claude Code ഉപയോഗിക്കുമ്പോൾ കമാൻഡ് സ്വയമേവ ലഭ്യമാകും.

## മികച്ച രീതികൾ

### '/code-review' ഉപയോഗിക്കുന്നു
 - മികച്ച പാലിക്കൽ പരിശോധനയ്ക്കായി വ്യക്തമായ CLAUDE.md ഫയലുകൾ പരിപാലിക്കുക
 - 80+ കോൺഫിഡൻസ് പരിധി വിശ്വസിക്കുക - തെറ്റായ പോസിറ്റീവുകൾ ഫിൽട്ടർ ചെയ്യപ്പെടുന്നു
 - നിസ്സാരമല്ലാത്ത എല്ലാ പുൾ അഭ്യർത്ഥനകളിലും പ്രവർത്തിപ്പിക്കുക
 - മനുഷ്യൻ്റെ അവലോകനത്തിനുള്ള ഒരു ആരംഭ പോയിൻ്റായി ഏജൻ്റ് കണ്ടെത്തലുകൾ അവലോകനം ചെയ്യുക
 - ആവർത്തിച്ചുള്ള അവലോകന പാറ്റേണുകളെ അടിസ്ഥാനമാക്കി CLAUDE.md അപ്ഡേറ്റ് ചെയ്യുക

### എപ്പോൾ ഉപയോഗിക്കണം
 - അർത്ഥവത്തായ മാറ്റങ്ങളുള്ള എല്ലാ പുൾ അഭ്യർത്ഥനകളും
 - നിർണായക കോഡ് പാതകളെ സ്പർശിക്കുന്ന PR-കൾ
 - ഒന്നിലധികം സംഭാവന ചെയ്യുന്നവരിൽ നിന്നുള്ള PR-കൾ
 - മാർഗ്ഗനിർദ്ദേശ പാലനം പ്രധാനമായ PR-കൾ

### എപ്പോൾ ഉപയോഗിക്കരുത്
 - അടച്ച അല്ലെങ്കിൽ ഡ്രാഫ്റ്റ് PR-കൾ (എങ്ങനെയുമിത് സ്വയമേവ ഒഴിവാക്കപ്പെടും)
 - നിസ്സാരമായ ഓട്ടോമേറ്റഡ് PR-കൾ (സ്വയമേവ ഒഴിവാക്കപ്പെടും)
 - ഉടനടി ലയിപ്പിക്കേണ്ട അടിയന്തിര ഹോട്ട്ഫിക്സുകൾ
 - ഇതിനകം അവലോകനം ചെയ്ത PR-കൾ (സ്വയമേവ ഒഴിവാക്കപ്പെടും)

## വർക്ക്ഫ്ലോ ഇൻ്റഗ്രേഷൻ

/code-review

# ഓട്ടോമേറ്റഡ് ഫീഡ്‌ബാക്ക് അവലോകനം ചെയ്യുക
# ആവശ്യമായ തിരുത്തലുകൾ വരുത്തുക

# ഓപ്ഷണലായി PR കമൻ്റായി പോസ്റ്റ് ചെയ്യുക
/code-review --comment

# തയ്യാറാകുമ്പോൾ ലയിപ്പിക്കുക
'''

# അവലോകന കമൻ്റുകൾ പോസ്റ്റ് ചെയ്യാൻ --comment ഫ്ലാഗ് ഉപയോഗിക്കുക
/code-review --comment
# അവലോകനം ഇതിനകം നിലവിലുണ്ടെങ്കിൽ ഒഴിവാക്കുക
'''

## ആവശ്യകതകൾ

 - GitHub ഇൻ്റഗ്രേഷനുള്ള Git റിപ്പോസിറ്ററി
 - GitHub CLI ('gh') ഇൻസ്റ്റാൾ ചെയ്യുകയും ആധികാരികമാക്കുകയും ചെയ്തിരിക്കണം
 - CLAUDE.md ഫയലുകൾ (ഓപ്ഷണൽ എന്നാൽ മാർഗ്ഗനിർദ്ദേശ പരിശോധനയ്ക്ക് ശുപാർശ ചെയ്യുന്നത്)

## ട്രബിൾഷൂട്ടിംഗ്

### അവലോകനത്തിന് കൂടുതൽ സമയമെടുക്കുന്നു

**പ്രശ്നം**: വലിയ PR-കളിൽ ഏജൻ്റുമാർക്ക് വേഗത കുറവാണ്

**പരിഹാരം**:
 - വലിയ മാറ്റങ്ങൾക്ക് ഇത് സാധാരണമാണ് - ഏജൻ്റുമാർ സമാന്തരമായി പ്രവർത്തിക്കുന്നു
 - 4 സ്വതന്ത്ര ഏജൻ്റുമാർ സമഗ്രത ഉറപ്പാക്കുന്നു
 - വലിയ PR-കളെ ചെറുതാക്കി വിഭജിക്കുന്നത് പരിഗണിക്കുക

### വളരെയധികം തെറ്റായ പോസിറ്റീവുകൾ

**പ്രശ്നം**: അവലോകനം യഥാർത്ഥമല്ലാത്ത പ്രശ്നങ്ങൾ ഫ്ലാഗ് ചെയ്യുന്നു

**പരിഹാരം**:
 - സ്ഥിരസ്ഥിതി പരിധി 80 ആണ് (ഇതിനകം മിക്ക തെറ്റായ പോസിറ്റീവുകളും ഫിൽട്ടർ ചെയ്യുന്നു)
 - പ്രാധാന്യമുള്ള കാര്യങ്ങളെക്കുറിച്ച് CLAUDE.md കൂടുതൽ വ്യക്തമാക്കുക
 - ഫ്ലാഗ് ചെയ്ത പ്രശ്നം യഥാർത്ഥത്തിൽ സാധുവാണോ എന്ന് പരിഗണിക്കുക

### അവലോകന കമൻ്റ് പോസ്റ്റ് ചെയ്തിട്ടില്ല

**പ്രശ്നം**: '/code-review' പ്രവർത്തിക്കുന്നു എന്നാൽ കമൻ്റ് ദൃശ്യമാകുന്നില്ല

**പരിഹാരം**:
ഇവ പരിശോധിക്കുക:
 - PR അടച്ചിട്ടുണ്ടോ (അവലോകനങ്ങൾ ഒഴിവാക്കപ്പെടും)
 - PR ഡ്രാഫ്റ്റാണോ (അവലോകനങ്ങൾ ഒഴിവാക്കപ്പെടും)
 - PR നിസ്സാരമോ/ഓട്ടോമേറ്റഡ് ആണോ (അവലോകനങ്ങൾ ഒഴിവാക്കപ്പെടും)
 - PR-ന് ഇതിനകം അവലോകനം ഉണ്ടോ (അവലോകനങ്ങൾ ഒഴിവാക്കപ്പെടും)
 - ≥80 സ്കോർ ചെയ്ത പ്രശ്നങ്ങളൊന്നും ഇല്ലേ (കമൻ്റ് ആവശ്യമില്ല)

### ലിങ്ക് ഫോർമാറ്റിംഗ് തകരാറിലായി

**പ്രശ്നം**: GitHub-ൽ കോഡ് ലിങ്കുകൾ ശരിയായി റെൻഡർ ചെയ്യുന്നില്ല

**പരിഹാരം**:
ലിങ്കുകൾ ഈ കൃത്യമായ ഫോർമാറ്റ് പാലിക്കണം:
'''
https://github.com/owner/repo/blob/[full-sha]/path/file.ext#L[start]-L[end]
'''
 - പൂർണ്ണ SHA ഉപയോഗിക്കണം (ചുരുക്കിയതല്ല)
 - '#L' നൊട്ടേഷൻ ഉപയോഗിക്കണം
 - കുറഞ്ഞത് 1 ലൈൻ സന്ദർഭമുള്ള ലൈൻ ശ്രേണി ഉൾപ്പെടുത്തണം

### GitHub CLI പ്രവർത്തിക്കുന്നില്ല

**പ്രശ്നം**: 'gh' കമാൻഡുകൾ പരാജയപ്പെടുന്നു

**പരിഹാരം**:
 - GitHub CLI ഇൻസ്റ്റാൾ ചെയ്യുക: 'brew install gh' (macOS) അല്ലെങ്കിൽ [GitHub CLI ഇൻസ്റ്റാളേഷൻ](https://cli.github.com/) കാണുക
 - ആധികാരികമാക്കുക: 'gh auth login'
 - റിപ്പോസിറ്ററിക്ക് GitHub റിമോട്ട് ഉണ്ടോ എന്ന് പരിശോധിക്കുക

## നുറുങ്ങുകൾ

 - **നിർദ്ദിഷ്ട CLAUDE.md ഫയലുകൾ എഴുതുക**: വ്യക്തമായ മാർഗ്ഗനിർദ്ദേശങ്ങൾ = മികച്ച അവലോകനങ്ങൾ
 - **PR-കളിൽ സന്ദർഭം ഉൾപ്പെടുത്തുക**: ഏജൻ്റുമാർക്ക് ഉദ്ദേശ്യം മനസ്സിലാക്കാൻ സഹായിക്കുന്നു
 - **കോൺഫിഡൻസ് സ്കോറുകൾ ഉപയോഗിക്കുക**: ≥80 പ്രശ്നങ്ങൾ സാധാരണയായി ശരിയാണ്
 - **മാർഗ്ഗനിർദ്ദേശങ്ങളിൽ ആവർത്തിക്കുക**: പാറ്റേണുകളെ അടിസ്ഥാനമാക്കി CLAUDE.md അപ്ഡേറ്റ് ചെയ്യുക
 - **സ്വയമേവ അവലോകനം ചെയ്യുക**: PR വർക്ക്ഫ്ലോയുടെ ഭാഗമായി സജ്ജീകരിക്കുക
 - **ഫിൽട്ടറിംഗിൽ വിശ്വസിക്കുക**: പരിധി അനാവശ്യമായവ തടയുന്നു

## കോൺഫിഗറേഷൻ

### കോൺഫിഡൻസ് പരിധി ക്രമീകരിക്കുന്നു

സ്ഥിരസ്ഥിതി പരിധി 80 ആണ്. ക്രമീകരിക്കുന്നതിന്, 'commands/code-review.md' എന്നതിലെ കമാൻഡ് ഫയൽ പരിഷ്ക്കരിക്കുക:
'''markdown
80-ൽ താഴെ സ്കോർ ഉള്ള ഏതൊരു പ്രശ്നവും ഫിൽട്ടർ ചെയ്യുക.
'''

'80' എന്നത് നിങ്ങൾ ഇഷ്ടപ്പെടുന്ന പരിധിയിലേക്ക് (0-100) മാറ്റുക.

### അവലോകന ഫോക്കസ് ഇഷ്ടാനുസൃതമാക്കുന്നു

ഏജൻ്റ് ടാസ്ക്കുകൾ ചേർക്കുന്നതിനോ പരിഷ്ക്കരിക്കുന്നതിനോ 'commands/code-review.md' എഡിറ്റ് ചെയ്യുക:
 - സുരക്ഷാ കേന്ദ്രീകൃത ഏജൻ്റുമാരെ ചേർക്കുക
 - പ്രകടന വിശകലന ഏജൻ്റുമാരെ ചേർക്കുക
 - പ്രവേശനക്ഷമത പരിശോധിക്കുന്ന ഏജൻ്റുമാരെ ചേർക്കുക
 - ഡോക്യുമെൻ്റേഷൻ ഗുണനിലവാര പരിശോധനകൾ ചേർക്കുക
